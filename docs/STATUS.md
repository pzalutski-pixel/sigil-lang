# Implementation Status

This is the single source of truth for what the Sigil compiler and runtime actually do today. The design specifications in [`docs/spec/`](spec/) describe the language as *intended*; this document records what is *implemented*. Where the two disagree, this document is correct.

Legend: **Done** = implemented and exercised by examples/tests · **Partial** = works in some cases, with known gaps or bugs · **Design only** = specified but not implemented (or non-functional).

## Compiler

| Capability | State | Notes |
|---|---|---|
| Lexer / parser / AST | Done | Full grammar per the language reference. |
| LLVM code generation | Done | Via `inkwell` (LLVM 18); native executables for the host target — x86-64 (Windows, Linux) and arm64 (macOS) both validated. |
| Type & size checking | Done | `int` / `float` / `bytes` / `string` (string is self-describing, length-prefixed — §2.5, no size); sizes: `int` 1/2/4/8, `float` 4/8, `bytes` any positive; no implicit conversion. Known limit: the front-end's `CALL`-argument type inference is *conservative* — a value read via `LOAD` is inferred as `int` and a `CALL` result as untyped — so an interpretation mismatch threaded through a `LOAD`/`CALL` chain may not be caught at the front-end (codegen still lowers per the handle's actual interpretation). Tightening this inference is a V2 item. |
| Handle-based memory & ownership | Done | Opaque handles, single ownership. Enforced: cannot free a borrowed INPUT handle (`FreeBorrowedHandle`); cannot free a handle still borrowed by a live `SPAWN` (`FreeWhileBorrowed`). Tested. |
| Memory-safety checks (CFG-aware, all paths) | Done | Static bounds checking (`offset + size ≤ allocation`; dynamic offsets emit a warning); double-free; use-after-free; uninitialized read (LOAD with no prior STORE on a path); memory-leak (ALLOC not freed on every path). All have unit tests. **These are *static* (compile-time) checks of the memory discipline, and they are now load-bearing at runtime: `ALLOC` allocates on the **heap** via a per-behavior scope allocator (`runtime/src/memory.c`), `FREE` actually frees, and `SCOPE`/`END_SCOPE` free a scope's allocations at its boundary — so a `SCOPE` inside a loop stays bounded rather than accumulating. Whatever is still live is freed when the behavior returns (a `JUMP` that skips an `END_SCOPE` is caught by the root scope's cascade, so it does not leak). A large `ALLOC` — e.g. a 64 KB read buffer — is a heap allocation, no longer a stack `alloca`. A CALL's **output buffer** is also heap-allocated via the scope allocator (a native like `read`/`receive` declares a 65536-byte output, which on the stack overflowed it: `0xC0000409`). Only small compiler scratch (boxing a scalar value to pass by pointer) stays a stack `alloca`.** The path-based checks now cover operations *inside* `SCOPE` blocks: a flatten pass (`cfg::flatten_scopes`) inlines scope bodies before the CFG is built and appends a synthetic `FREE` for each scoped `ALLOC` (so `END_SCOPE`'s auto-cleanup doesn't read as a leak). Validated: an uninitialized read inside a `SCOPE` is caught (`E0304`), and a clean scoped alloc is not flagged. (Limit: a scope body that `JUMP`s out of itself before `END_SCOPE` isn't specially handled; current leaves don't write that.) |
| `writes_output` guarantee | Done | "All outputs written on all paths," via CFG path analysis. |
| atomic-on-`SHARED` enforcement | Done | Non-atomic LOAD/STORE on a `SHARED` handle is a compile error (`NonAtomicSharedAccess`); use `ATOMIC_*`. Tested. |
| Contract hashing | Done | SHA-256 over the contract; dependencies pinned by hash. |
| 43 primitive operations | Done | See the language reference. |
| Leaf / composite separation | Done | A composite (`COMPOSITION`/`ENTRY`) may only wire — `CALL`/`SET`/control/concurrency plus constant bindings; it may not compute or touch memory (no `ALLOC`/`FREE`/`STORE`/`LOAD`/arithmetic), error `E0509`. A leaf (`IMPLEMENTATION`) may not `CALL`, error `E0510`. This makes the model's quarantine — algorithmic logic lives only in leaves — a compiler-enforced rule, not a convention. To route on a result field, BRANCH on it directly. Tested. |
| `no_alloc` guarantee | Done | Satisfied by no ALLOC, or all ALLOC inside a `SCOPE` (freed at `END_SCOPE`). The analyzer tracks scope depth, so a scoped ALLOC no longer counts as escaping. Tested. |
| `pure` guarantee | Done (structural) | Within a behavior it rejects CHANNEL operations, non-OUTPUT writes, **and pattern-`MEMORY` access** (declaring `MEMORY` means touching persistent state — not pure). A whole-graph pass also enforces **transitivity**: a `pure` behavior depending on a declared-non-pure one is a compile error (`TransitivePurityViolation`). Tested. Defined structurally (no channels / no non-output writes / no MEMORY / no non-pure deps), not as a semantic referential-transparency proof. |
| `all_paths_terminate` | Done (structural) | Weakened, decidable check: every block reachable from entry must be able to reach an exit. Permits ordinary loops (they structurally connect to an exit); rejects only control flow that can never reach END (an exit-less loop). O(V+E), tested. Does NOT prove semantic termination (halting problem) — only that the CFG has no dead-end. |
| Path enumeration | Partial | Exponential in branches; a polynomial dataflow analysis exists in the code (`cfg::analyze_data_flow`) but is not wired in. Fine for the small behaviors seen so far; a pathological many-branch behavior could blow up. |
| Whole-graph dependency checks | Done | A pass over the `REQUIRES` graph enforces **transitive purity**, rejects **circular dependencies**, and verifies **dependency hash pins** — a `REQUIRES name@hash` whose pin ≠ the dependency's current contract hash is a compile error, **including for linked library (stdlib) dependencies** (this is the "the hash is the memory; a changed dependency is caught" property, now enforced end-to-end). Tested (`graph/validate.rs`), wired into the executable compile path (`main.rs` Phase 5.5). Scope: it runs on the program's dependency closure; the `--lib` (library) compile path doesn't run it yet. |
| Cross-behavior *port* completeness | Outputs: Done · Inputs: argument-checked | **Outputs-consumed is enforced; inputs are argument-checked (not yet full graph-level port-sourcing).** Outputs-consumed — in a composition every output a `CALL` produces must be *consumed* (routed to another `CALL`, used as a `BRANCH` condition, or written to an `OUTPUT`) or explicitly dropped with `DISCARD`; an unconsumed output is `E0511` (§7.8). Inputs — `CALL` argument count/type checking catches wrong-arity/wrong-type arguments; the stronger graph-level "every input *port* has a source" check lives in `graph/gaps.rs` (built and tested) but is not wired on V1 (which reconstructs wiring from text), so input-sourcing is verified at the call-argument level, not the whole-graph level. The explicit `DISCARD` is what makes ignoring a value a deliberate, recorded act rather than a silent omission — a side-effect call like `CALL println msg` is fine (`println` is a sink with no outputs), but dropping a real result or error is a compile error until acknowledged. Tested; all bundled examples comply. Scope: composition behaviors (a leaf produces no call-outputs; an `ENTRY`'s outputs are the process boundary). |
| Compiler-inferred parallelism | Design only | Independent `CALL`s run sequentially; the compiler does not auto-parallelize. |

## Runtime (C)

| Capability | State | Notes |
|---|---|---|
| Core native behaviors (OS edge) | Partial | The set backing the stdlib's NATIVE behaviors — file, console, sockets, process/env, clock (`runtime/src/{file,console,net,os,time}.c`). Covers everything the stdlib and examples use; further OS-edge candidates (e.g. DNS resolution) are not built. Everything above this edge is pure Sigil — see the Standard library row. |
| Concurrency runtime: `SPAWN` / `WAIT` / `WAIT_ALL` / `WAIT_ANY` / `CHANNEL` / `CHANNEL_SEND` / `RECEIVE` / `CLOSE` | Done | Green-thread worker pool on **real OS threads**, with bounded multi-producer/multi-consumer channels. The compiler lowers these to runtime calls, and the `spawn-test`, `parallel-test`, `channel-test`, and `producer-consumer` examples build and run. The *compile-time* concurrency-safety checks (atomic-on-`SHARED`, free-while-borrowed) are enforced — see the compiler table. Caveats: `WAIT` blocks until the spawned task completes (the concurrency examples verify this) and yields a completion status, **not** a result value — a spawned pattern has no OUTPUT contract, so data flows back via channels (and a failure status isn't surfaced; tasks are marked completed). `CHANNEL_RECEIVE` returns the received **value** (validated: send 42 → receive 42), and `WAIT_ANY` blocks on a table-wide completion condvar and returns the **index** of the task that finished (validated: a slow worker h0 + fast worker h1 → `which=1`); channel and socket table lazy-init is race-free (`sigil_once`). Channels are never destroyed in the current codegen, so `get_channel` returning a table pointer used outside the table lock is safe today (a future destroy path would need refcounting). The compiler does not auto-parallelize independent calls; no performance benchmarks (platform coverage: see the platform row). (An earlier note here claimed a large pattern-`MEMORY bytes` buffer doesn't round-trip; that was a kv-store null-termination *logic* bug, since fixed — kv-store now uses `MEMORY store bytes 33864` and round-trips correctly, verified by running it.) |
| Platform support | Validated on Windows, Linux, macOS | Windows is the development platform (MSVC/clang-cl). The POSIX paths (`platform.h`, `file.c`, `net.c`, `console.c`: pthreads, BSD sockets, POSIX I/O) are built and exercised by CI (`.github/workflows/ci.yml`) on Linux x86-64 and macOS arm64 — compiler test suite, runtime, stdlib, and all example byte-checks green (first green run 2026-06-11). Cross-*compilation* (`--target`) is not built; the compiler targets its host. |

The build-time `--fix-hashes` flag rewrites hashes in place; its zero/placeholder-mangling bug is fixed. This was the single biggest friction point in the first two experiment runs (every agent hand-rolled the hash algorithm); the `--hash` tool removed it — in the later runs, 0/6 agents hand-rolled the hash. |

## Summary

**Node-level checking is substantial.** Within a single behavior the compiler enforces type/size rules, a CFG-aware memory-safety pass (bounds, double-free, use-after-free, uninitialized read, leaks), ownership (no freeing borrowed or spawn-borrowed handles), output-on-all-paths, atomic access to `SHARED` memory, the `no_alloc` / `pure` / `writes_output` guarantees, and structural termination — all with unit tests. It also enforces the **leaf/composite separation** (composites wire; leaves compute) and, across behaviors, **transitive purity**, **no circular dependencies**, and **cross-behavior port completeness** — both inputs-sourced (via CALL argument checking) and **outputs-consumed** (every CALL output in a composition is routed or explicitly `DISCARD`ed, else `E0511`, §7.8). Outputs-consumed is the flagship structural-completeness property, now enforced for V1 compositions via a minimal explicit-`DISCARD` construct rather than waiting on the full V2 grammar. The concurrency *runtime* works (green threads, channels) with its core compile-time safety checks enforced; what's missing there is auto-parallelization and full `WAIT` result-passing. Cross-platform code is written (POSIX branches throughout the runtime); only Windows is validated.

## How this is verified

- **`cargo test`** (`compiler\build.bat --test`) covers the compiler, **including the safety checks above** — there are unit tests for double-free, use-after-free, uninitialized read, leak detection, free-borrowed/free-while-spawn-borrowed, and atomic-on-`SHARED`. What it does **not** exercise is the concurrency *runtime* (actual thread execution).
- **The concurrency runtime is verified by the example programs:** `examples\build.bat` builds all examples (including `spawn-test`, `parallel-test`, `channel-test`, `producer-consumer`), and running those executables demonstrates SPAWN/WAIT/CHANNEL working on real threads. Treat them as its integration tests until equivalent automated coverage exists.
